# 徒步轨迹分享 · 敏感地点遮蔽

上传含时间的 GPX 轨迹，自动统计**分段配速**、**海拔剖面 / 累计爬升**、**持续陡坡**
（100 米窗口坡度 ≥ 8% 的连续区间）、**停留识别**
（停留 / 移动时长）并检测**单点漂移跳点**（可下载修复后的 GPX）；支持按 1～100 米
误差阈值做 **Douglas-Peucker 轨迹精简**（预览叠加精简线、显示前后点数、可下载精简后的
GPX）；可再上传第二条轨迹做**双人轨迹相遇分析**（时间重叠范围内距离 ≤ 50 米且持续
≥ 60 秒的区间，列出起止时间、时长与最近距离）；可在预览图上添加**命名检查点**
（最多 10 个圆形检查点，半径 1～1000 米、默认 50 米，与遮蔽圆分别管理），自动列出
**每次进入 / 离开时间与停留秒数**；在**无底图**预览图上点击敏感地点
（如家、公司）并设定遮蔽半径，系统按**轨迹线段与遮蔽圆的交点**精确裁切，导出为
**互不连接的 GPX `trkseg`** 后再分享。

- 后端：Python / FastAPI（几何裁切与配速统计在服务端完成）
- 前端：原生 JavaScript + Canvas（无任何框架、无地图底图依赖）

## 一条命令启动

```bash
docker compose up --build
```

依赖安装与初始化全部在镜像构建和容器启动时自动完成，无需任何额外步骤。

## 访问地址

- 网页：**http://localhost:8000**（端口 8000）
- API：与网页同端口，路径前缀 `/api`（如 `POST http://localhost:8000/api/simplify`）；
  交互式接口文档见 **http://localhost:8000/docs**

## 使用流程

1. **上传 GPX**：选择含 `<time>` 的 GPX 文件（缺少时间会被拒绝并提示）。可用
   `examples/sample.gpx` 快速体验。
2. **查看分段配速**：上传后页面下方自动按**每段里程**（0.1～10 公里，默认 1 公里，
   可修改后自动重算）列出每段的距离、耗时、分/公里配速与起止时间。
3. **查看海拔剖面**：页面底部自动绘制**按里程展开的海拔曲线**，并给出**总爬升 / 总下降**
   与海拔范围；轨迹无海拔信息时显示"无海拔数据"。
4. **查看持续陡坡**：页面自动复用上述平滑海拔剖面，列出**持续陡坡区间的起止里程、
   方向与最大绝对坡度**（上坡 ≥ 8%、下坡 ≤ −8%，合并后总长 ≥ 100 米），并在海拔图上
   以橙色（上坡）/ 青绿色（下坡）色带标出；无海拔或没有符合区间时显示明确空态。
5. **查看单点漂移修复**：页面自动检测**跳点**（GPS 单点漂移），命中点以橙色"漂"标记在
   预览图上，并列出命中明细与**修复前 / 修复后里程**；点击"下载修复后的 GPX"得到删除
   跳点后的轨迹。遮蔽裁切、配速与海拔统计始终使用**原始轨迹**，不受修复影响。
6. **查看停留识别**：页面自动识别**停留**（同一地点逗留 ≥ 3 分钟），停留位置以紫色"停"
   标记在预览图上，并列出每次停留的位置、起止时间与时长，以及**全程记录 / 停留 / 移动时长**。
7. **轨迹精简**：页面按**误差阈值**（1～100 米，默认 10 米，修改后自动重算）对原始轨迹做
   Douglas-Peucker 精简，精简线以青绿色叠加在预览图上，并显示**精简前 / 后点数**与距离；
   点击"下载精简后的 GPX"得到与预览一致的精简轨迹。遮蔽裁切、配速、海拔、漂移与停留统计
   始终使用**原始轨迹**，不受精简影响。
8. **双人轨迹相遇**（可选）：在"双人轨迹相遇"区块**再上传一条含时间的 GPX** 作为对比轨迹
   （复用同一上传接口），页面自动分析并列出**每次相遇的起止时间、持续时长与最近距离**，
   相遇位置以粉红色"遇"标记在预览图上；无相遇时显示空结果。对比轨迹仅用于相遇分析，
   不影响当前轨迹的遮蔽、配速、海拔、陡坡、漂移、停留与精简结果。
9. **添加检查点并查看到访**（可选）：把面板顶部的编辑模式切换为**检查点**后，在预览图上
   **点击**即可添加圆形检查点（最多 10 个，半径 1～1000 米、默认 50 米，与遮蔽圆分别管理、
   互不影响）；每个检查点可在列表中**命名**、单独修改半径或删除。页面自动逐检查点列出
   **每次进入、离开时间及停留秒数**（基于原始轨迹计算，不修改原轨迹），未到访的检查点
   显示"未到访"空态；检查点以靛蓝色圆圈与名称标在预览图上。
10. **设置遮蔽**：把编辑模式切回**遮蔽圆**，在右侧预览图上**点击**敏感地点即添加遮蔽圆，
    半径在左侧面板设定（添加前设定新圆半径；已有圆可在列表中单独修改或删除）。
11. **查看裁切结果**：页面实时显示 **隐藏段数**、**裁切前距离**、**裁切后距离** 与可见分段数；
    蓝色为可见轨迹，红色虚线为被隐藏段。
12. **下载**：点击"下载遮蔽后的 GPX"，得到一条 `trk` 下多个互不连接的 `trkseg`。

## 分段配速规则（实现要点）

- **按原始 trkseg 分别累计**：每个原始 `trkseg` 独立从 0 起算 haversine 球面距离，
  配速段不跨分段边界合并；trkseg 之间的时间间隔不计入耗时。
- **边界时间插值**：采样线段跨越一个或多个里程边界时，边界时间按**距离比例**在线段
  起止时间之间线性插值。
- **末尾不足一段也列出**：剩余不足一个整段的部分作为最后一段给出实际距离与配速。
- **时间不递增**：同一 trkseg 内相邻轨迹点时间相同或倒退时无法插值，接口返回 400
  并在页面提示"无法计算配速"。
- **零里程段**：距离为 0 的段（如整段原地不动）配速显示为 "—"，不显示无穷大。

## 海拔剖面与累计爬升规则（实现要点）

- **基于原始轨迹**：分析使用上传时保存的原始 GPX（各原始 `trkseg`），与遮蔽裁切、
  配速统计互不影响；设置遮蔽圆不会改变海拔分析结果。
- **连续有效海拔区间**：每个 `trkseg` 内，`ele` 非空的极大连续子序列各自构成一个区间；
  缺失海拔处断开，不跨原始分段或缺口插值。
- **20 米重采样**：区间内按 haversine 水平里程每 **20 米**线性插值采样海拔，
  区间起点与终点始终保留（末段不足 20 米也保留终点）。
- **三点中位数**：对采样海拔做三点中位数滤波（序列端点保持原值），抑制孤立尖峰。
- **5 米反向确认峰谷**：趋势极值被反向变化超过 **5 米**时确认一个峰/谷，
  累计已确认的上升与下降；区间末尾未确认的变化也计入；各区间独立累计后求和。
- **无海拔数据**：全程无任何有效海拔时接口返回 `has_ele=false`、爬升/下降为 `null`，
  页面显示"无海拔数据"而不是 0 米爬升。

## 持续陡坡规则（实现要点）

- **复用平滑海拔剖面**：直接消费海拔分析的结果——同样的**连续有效海拔区间**切分
  （原始 `trkseg` 内 `ele` 非空的极大连续子序列）、同样的 **20 米重采样**与
  **三点中位数滤波**序列；与遮蔽裁切、配速、漂移修复、停留、精简互不影响。
- **完整 100 米窗口**：在每个连续有效海拔区间内，窗口跨度为 **100 米**（5 个 20 米
  采样间隔），从区间起点每 **20 米**前移一次；只使用首尾都落在重采样网格上的完整窗口，
  区间首尾各 50 米、以及末端不足 100 米的部分不会被标记（不补点、不外推）。
- **坡度口径**：坡度 = 窗口首末**平滑海拔之差** ÷ 100 米 × 100%；
  **上坡 ≥ 8%** 或**下坡 ≤ −8%**（边界值命中）时，标记**窗口中心对应的 20 米里程区间**
  （窗口中心 ±10 米，标记边界恰在 20 米网格上）。
- **同向相邻合并**：沿里程顺序把**相邻且方向相同**的标记合并为一个陡坡区间；
  方向相反（上坡/下坡相邻）或中间被未标记窗口隔开（如平缓段）都不合并；
  合并后**总长至少 100 米**（恰好 100 米列出，即至少 5 个连续同向标记）才给出
  **起止里程、方向（上坡/下坡）与最大绝对坡度**（区间内最陡窗口的有符号坡度，%）。
- **边界不合并**：每个连续有效海拔区间独立分析，**原始 `trkseg` 边界**与
  **缺失海拔处**天然断开，绝不跨分段或缺口合并；输出里程为**全程水平里程**坐标
  （与海拔图 x 轴一致），并附原始 `seg_index`。
- **空态**：全程无任何有效海拔时返回 `has_ele=false`、`sections` 为空，页面显示
  "无海拔数据，无法分析持续陡坡"；有海拔但无符合区间时 `sections` 为空数组，页面显示
  "未发现持续陡坡"的明确空态。

## 单点漂移修复规则（实现要点）

- **按原始 trkseg 独立判定**：只考察同一 `trkseg` 内连续三点 A→B→C 中的中间点 B，
  不跨分段边界拼合判定；每个 `trkseg` 的首尾点不参与判定，始终保留。
- **跳点判定**（同时满足三条）：
  1. 进出两段速度均超过 **12 米/秒**（A→B 与 B→C）；
  2. 绕过该点的首尾速度不超过 **12 米/秒**（A→C）；
  3. 该点到首尾线段 AC 的**水平最短距离**超过 **40 米**（局部切平面投影中计算）。
- **时间校验**：`trkseg` 内相邻点时间必须严格递增；遇零时差或倒序，接口返回 400
  并给出"第 N 个 trkseg 中第 i→i+1 个轨迹点的时间未递增"的明确提示。
- **逐轮修复**：按原始点顺序扫描，每轮只删除**最早命中**的一个跳点，删除后以剩余点
  重新计算，直到无命中；被删跳点不参与后续判定（可能使原本不满足条件的相邻点
  在新一轮被判定）。
- **修复结果独立**：修复只用于"单点漂移修复"区块的展示与修复后 GPX 导出；
  遮蔽裁切、分段配速、海拔分析均继续使用上传时保存的原始轨迹。
- **里程统计**：修复前 / 修复后里程均按 haversine 球面距离逐段累计，修复后里程
  为删除全部命中跳点后的剩余轨迹里程。

## 停留识别规则（实现要点）

- **按原始 trkseg 独立判定**：按时间顺序处理每个原始 `trkseg`，不跨分段边界拼合；
  基于上传时保存的原始轨迹计算，与遮蔽裁切、配速、海拔、漂移修复互不影响。
- **锚点扩展**：以候选首点为**锚**向后扩展，逐一纳入后续点，只要新点到**锚点**的
  水平距离（haversine）不超过 **30 米**就继续扩展（是相对于锚点判定，而非相邻点链式判定）。
- **越界即结算**：遇到首个超出 30 米的点时，当前候选区间（锚到前一个点）立即结算，
  越界点成为下一个候选首点，**区间互不重叠**；分段末尾同样结算。
- **停留条件**：候选区间**首末至少相隔 3 分钟**才记为一次停留，否则丢弃；
  停留位置取区间内各点经纬度的算术平均。
- **时间校验**：`trkseg` 内相邻采样时间必须严格递增；遇零时差或倒序，接口返回 400
  并给出"第 N 个 trkseg 中第 i→i+1 个轨迹点的时间未递增"的明确提示。
- **记录中断**：相邻采样间隔超过 **10 分钟**视为记录中断，空档**不计入任何时长**
  （既不计入全程记录时长，也不计入停留时长），但不结算、不打断当前候选区间。
- **时长口径**：全程**记录时长** = 各 `trkseg` 内有效相邻采样时差（≤ 10 分钟）之和
  （分段间隔不计入，与分段配速口径一致）；**停留时长** = 各停留区间内有效相邻采样
  时差之和（区间互不重叠，可安全求和）；**移动时长** = 记录时长 − 停留时长。

## 轨迹精简规则（实现要点）

- **基于原始轨迹**：精简使用上传时保存的原始 GPX（各原始 `trkseg`），与遮蔽裁切、
  配速、海拔、漂移修复、停留识别互不影响；精简不会修改上传的原轨迹。
- **逐个 trkseg 独立处理**：每个原始 `trkseg` 单独精简，精简结果不跨分段连线，
  导出的每个 `trkseg` 与原始分段一一对应。
- **局部米制投影**：段内经纬度投影到**以该段首点为原点**的局部等距圆柱平面（米），
  在平面内计算距离；常用轨迹尺度下与大地线的偏差为亚毫米级。
- **Douglas-Peucker 拆分**：每个区间取到**首尾有限线段**距离最远的点，仅当该距离
  **超过**误差阈值（恰好等于不拆）时才保留该点并继续拆分两侧区间；
  **首尾重合**（零长度线段）时退化为中间点到端点的距离。
- **首尾与属性保留**：每段首尾点始终保留；选中点直接引用原始轨迹点，
  经纬度、海拔、时间原样保留，不做插值或修改。
- **边界情形**：单点段、两点段、重复点（含全部重合）均可正常处理。
- **迭代实现**：用显式栈代替递归，十万点级别的输入不会触发递归栈溢出。
- **预览与下载一致**：页面叠加的精简线与下载的 GPX 使用同一接口、同一算法与参数，
  结果逐点一致；误差阈值超出 1～100 米时接口返回 422（页面输入自动收敛到范围内）。

## 双人轨迹相遇规则（实现要点）

- **基于原始轨迹**：两条轨迹均使用上传时保存的原始 GPX（各原始 `trkseg`），与遮蔽裁切、
  配速、海拔、漂移修复、停留识别、轨迹精简互不影响；对比轨迹复用 `POST /api/upload`
  上传，同样只保存在内存。
- **带时间的线段**：两条轨迹各自按 `trkseg` 内**相邻点**构造线段，线段内位置按时间
  **线性插值**；`trkseg` 内相邻点时间必须严格递增，遇零时差或倒序接口返回 400，
  并指明是"当前轨迹"还是"对比轨迹"的第几个 `trkseg`。
- **断档不插值**：相邻采样间隔超过 **10 分钟**视为断档，断档处不构造线段；
  `trkseg` 边界同样不连接——每条线段只在其采样间隔内有效，
  **不跨断档或 trkseg 虚构相遇**。
- **仅比较时间重叠的线段**：对每对时间重叠的线段，把端点投影到以四端点平均位置为
  原点的**局部米制平面**（等距圆柱投影，50 米判定尺度下投影误差可忽略）；
  相对位置关于时间是线性的，解 `|r(t)|² = 50²` 得到距离不超过 **50 米**的候选区间
  （相切只算瞬时接触，不构成区间）。
- **合并与过滤**：候选区间按时间排序后，**相接（或重叠）的区间合并**；
  合并后持续**不足 60 秒**的不列出（恰好 60 秒列出）。
- **结果口径**：每次相遇给出起止时间、持续时长、**最近距离**及其出现时刻，
  以及最近时刻两人位置的中点（页面"遇"标记）；无相遇时 `encounters` 为空数组，
  页面显示空结果。

## 检查点到访规则（实现要点）

- **基于原始轨迹**：到访分析使用上传时保存的原始 GPX（各原始 `trkseg`），
  **不修改原轨迹**，与遮蔽裁切、配速、海拔、漂移修复、停留识别、精简、相遇互不影响；
  检查点与遮蔽圆**分别管理**（前端各自独立的列表与编辑模式，后端各自独立的接口）。
- **检查点口径**：最多 **10 个**圆形检查点（超出返回 422），半径 **1～1000 米**、
  默认 **50 米**（超出范围返回 422），每个检查点可命名（最长 50 字符）。
- **圆内区间**：对每个检查点独立分析——在**圆心局部米制投影**（等距圆柱，与遮蔽裁切
  同一线段-圆求交）中求每条采样线段落在圆内的参数区间，**进出时间按线段比例**在线段
  起止时间之间线性插值；**两端都在圆外但线段穿圆**（判别式 > 0）同样识别，
  **相切**（判别式 = 0）只是瞬时接触，不计入。
- **断档与分段**：相邻采样间隔超过 **600 秒**视为断档，断档处不构造线段、不插值，
  断档两侧的圆内区间不合并；`trkseg` 边界同样断开，**绝不跨 trkseg 或断档合并**。
- **合并与过滤**：同一检查点、同一 `trkseg` 内连续（相接或重叠）的圆内区间合并为
  一次到访，**仅列出正时长**的到访（零时长区间不计）；到访起止落在采样点上
  （该点在圆内）时直接使用**该连续记录的端点原始时间**，不做外推。
- **时间校验**：`trkseg` 内相邻点时间必须严格递增；遇零时差或倒序，接口返回 400
  并给出"第 N 个 trkseg 中第 i→i+1 个轨迹点的时间未递增"的明确提示。
- **结果口径**：逐检查点返回每次到访的进入 / 离开时间（ISO）与停留秒数，
  以及到访次数与累计停留秒数；未到访的检查点 `visits` 为空数组，页面显示"未到访"空态。

## 裁切规则（实现要点）

- **穿越识别**：对每个原始采样线段与每个遮蔽圆求解析交点（局部切平面投影中解二次方程），
  即使相邻两个采样点都在圆外、但线段穿越圆，也会被识别并裁开。
- **时间插值**：交点处的时间（及海拔）按交点在线段上的比例 `t` 线性插值，
  导出时精确到毫秒。
- **分段边界**：可见轨迹不跨原始 `trkseg` 边界合并；每段连续可见部分导出为一个独立
  `trkseg`，隐藏部分不出现在导出文件中。
- **距离统计**：裁切前/后距离均用 haversine 大地线距离累计，裁切后距离包含插值边界点。
- **精度说明**：遮蔽判定在圆心切平面投影中进行，常用半径（数十米至数公里）下与大地线
  的偏差为亚厘米级；导出的边界点经纬度保留 7 位小数（约 1 cm）。

## API 摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/upload` | 表单上传 GPX，返回 `track_id`、轨迹点与统计 |
| `POST` | `/api/mask` | `{track_id, circles:[{lat,lon,radius_m}]}` → 可见/隐藏分段、隐藏段数、裁切前后距离 |
| `POST` | `/api/export` | 同上参数，返回多 `trkseg` 的 GPX 文件下载 |
| `POST` | `/api/pace` | `{track_id, split_km?}` → 分段配速（见下） |
| `POST` | `/api/elevation` | `{track_id}` → 海拔剖面与总爬升/总下降（见下） |
| `POST` | `/api/steep-sections` | `{track_id}` → 持续陡坡区间列表（见下） |
| `POST` | `/api/drift` | `{track_id}` → 单点漂移检测结果与修复前后里程（见下） |
| `POST` | `/api/drift/export` | `{track_id}` → 删除跳点后的 GPX 文件下载 |
| `POST` | `/api/stays` | `{track_id}` → 停留识别结果与记录/停留/移动时长（见下） |
| `POST` | `/api/simplify` | `{track_id, tolerance_m?}` → 精简后分段、前后点数与距离（见下） |

| `POST` | `/api/encounters` | `{track_id, other_track_id}` → 双人轨迹相遇列表（见下） |
| `POST` | `/api/checkpoint-visits` | `{track_id, checkpoints:[{lat,lon,radius_m?,name?}]}` → 逐检查点到访列表（见下） |

### `POST /api/pace` 分段配速

- **参数**：`track_id`（必填，上传返回值）；`split_km`（可选，每段里程，**0.1～10 公里**，
  默认 **1**，超出范围返回 422）。
- **返回**：按原始 `trkseg` 分组的段列表，每段含 `distance_m`（距离）、`duration_s`（耗时）、
  `pace_min_per_km`（分/公里配速，零里程段为 `null`）、`start_time` / `end_time`
  （ISO 时间，段边界为插值时刻）；另附全程合计 `totals`。
- **错误**：轨迹相邻点时间不递增时返回 `400` 与中文提示；`track_id` 不存在返回 `404`。

示例：

```bash
curl -X POST http://localhost:8000/api/pace \
  -H "Content-Type: application/json" \
  -d '{"track_id": "<上传返回的 track_id>", "split_km": 0.5}'
```

### `POST /api/elevation` 海拔剖面与累计爬升

- **参数**：`track_id`（必填，上传返回值）。
- **返回**：`has_ele`（是否存在有效海拔）、`ascent_m` / `descent_m`（总爬升/总下降，
  无海拔时为 `null`）、`distance_m`（全程水平里程）、`ele_min` / `ele_max`（平滑后海拔范围）、
  `sample_step_m`（20）与 `reversal_threshold_m`（5）两个口径常量，以及 `runs` 剖面列表；
  每个 run 含 `seg_index`（原始 `trkseg` 序号）、`start_m`（区间起点的全程里程）和
  `points`（`[{d, ele}]`，`d` 为全程里程坐标，缺口与分段处断开）。
- **错误**：`track_id` 不存在返回 `404`。

示例：

```bash
curl -X POST http://localhost:8000/api/elevation \
  -H "Content-Type: application/json" \
  -d '{"track_id": "<上传返回的 track_id>"}'
```

### `POST /api/steep-sections` 持续陡坡分析

- **参数**：`track_id`（必填，上传返回值）。无额外参数，口径固定为
  100 米窗口、20 米前移、坡度阈值 ±8%、合并后最小总长 100 米。
- **返回**：`has_ele`（是否存在有效海拔）、`distance_m`（全程水平里程）、`sections`
  （陡坡区间列表，按里程先后；每段含 `seg_index`（原始 `trkseg` 序号）、
  `start_m` / `end_m`（全程里程坐标的起止）、`length_m`（长度，米）、
  `direction`（`"up"` 上坡 / `"down"` 下坡）、`max_grade_pct`（区间内有符号的
  最大绝对坡度，%，下坡为负）、`window_count`（合并的 20 米标记数））与
  `thresholds`（口径：`window_m=100`、`window_step_m=20`、`grade_threshold_pct=8`、
  `min_section_m=100`）。
- **空态**：无任何有效海拔时 `has_ele=false` 且 `sections` 为空；
  有海拔但无符合区间时 `has_ele=true`、`sections` 为空数组；
  `track_id` 不存在返回 `404`。

示例：

```bash
curl -X POST http://localhost:8000/api/steep-sections \
  -H "Content-Type: application/json" \
  -d '{"track_id": "<上传返回的 track_id>"}'
```

### `POST /api/drift` 单点漂移检测与修复

- **参数**：`track_id`（必填，上传返回值）。
- **返回**：`hit_count`（命中跳点数）、`hits`（命中明细：原始 `seg_index` / `point_index`、
  经纬度、时间、进/出/绕过速度 `speed_in_mps` / `speed_out_mps` / `speed_bypass_mps`、
  到首尾线段距离 `offset_m`）、`distance_before_m` / `distance_after_m`（修复前后里程）、
  `points_before` / `points_after`（修复前后轨迹点数）与 `thresholds`
  （判定口径：`max_speed_mps=12`、`min_offset_m=40`）。
- **错误**：轨迹相邻点时间未递增（零时差或倒序）时返回 `400` 与中文提示；
  `track_id` 不存在返回 `404`。
- **`POST /api/drift/export`**：参数相同，返回删除全部命中跳点后的 GPX 下载
  （保留原始 `trkseg` 结构与每段首尾点，文件名为 `<轨迹名>-fixed.gpx`）。

示例：

```bash
curl -X POST http://localhost:8000/api/drift \
  -H "Content-Type: application/json" \
  -d '{"track_id": "<上传返回的 track_id>"}'
```

### `POST /api/stays` 停留识别与记录/移动时长

- **参数**：`track_id`（必填，上传返回值）。
- **返回**：`stays`（停留列表，按时间先后；每次停留含原始 `seg_index` 与区间内
  `start_index` / `end_index`、位置 `lat` / `lon`（区间内各点均值）、
  `start_time` / `end_time`（ISO 时间）、`duration_s`（停留时长，不含记录中断空档）、
  `points`（区间内轨迹点数））、`recording_s`（全程记录时长，有效相邻采样时差之和）、
  `stay_total_s`（全程停留时长）、`moving_s`（全程移动时长 = 记录时长 − 停留时长）与
  `thresholds`（判定口径：`radius_m=30`、`min_stay_s=180`、`max_gap_s=600`）。
- **错误**：轨迹相邻采样时间未递增（零时差或倒序）时返回 `400` 与中文提示；
  `track_id` 不存在返回 `404`。

示例：

```bash
curl -X POST http://localhost:8000/api/stays \
  -H "Content-Type: application/json" \
  -d '{"track_id": "<上传返回的 track_id>"}'
```

### `POST /api/simplify` 轨迹精简（Douglas-Peucker）

- **参数**：`track_id`（必填，上传返回值）；`tolerance_m`（可选，误差阈值，
  **1～100 米**，默认 **10**，超出范围返回 422）。
- **返回**：`tolerance_m`（实际使用的阈值）、`segments`（精简后分段，与原始
  `trkseg` 一一对应，每点含 `lat` / `lon` / `ele` / `time`，均为原始轨迹点）、
  `points_before` / `points_after`（精简前后轨迹点数）、
  `distance_before_m` / `distance_after_m`（精简前后距离，haversine 逐段累计）。
- **算法**：逐个 `trkseg` 把经纬度投影到以该段首点为原点的局部米制平面，
  以点到**有限线段**的距离选取最大偏差点，超过阈值才继续拆分；首尾重合时按
  点到端点的距离处理；显式栈迭代实现，十万点输入不会递归栈溢出。
- **错误**：`track_id` 不存在返回 `404`。
- **`POST /api/simplify/export`**：参数相同，返回精简后的 GPX 下载
  （保留原始 `trkseg` 结构，文件名为 `<轨迹名>-simplified.gpx`），
  与页面预览逐点一致；不修改上传的原轨迹。

示例：

```bash
curl -X POST http://localhost:8000/api/simplify \
  -H "Content-Type: application/json" \
  -d '{"track_id": "<上传返回的 track_id>", "tolerance_m": 20}'
```

### `POST /api/encounters` 双人轨迹相遇

- **参数**：`track_id`（当前轨迹，必填）；`other_track_id`（对比轨迹，必填——
  对比轨迹同样通过 `POST /api/upload` 表单上传获得 `track_id`）。
- **返回**：`encounters`（相遇列表，按时间先后；每次含 `start_time` / `end_time`
  （ISO 时间）、`duration_s`（持续秒数）、`min_distance_m`（区间内最近距离，米）、
  `closest_time`（最近距离出现时刻）、`lat` / `lon`（最近时刻两人位置的中点））与
  `thresholds`（判定口径：`radius_m=50`、`min_meet_s=60`、`max_gap_s=600`）；
  无相遇时 `encounters` 为空数组。
- **错误**：任一轨迹相邻点时间未递增（零时差或倒序）时返回 `400` 与中文提示
  （指明是当前轨迹还是对比轨迹）；任一 `track_id` 不存在返回 `404`。

示例（两条轨迹都先经 `/api/upload` 上传）：

```bash
curl -X POST http://localhost:8000/api/encounters \
  -H "Content-Type: application/json" \
  -d '{"track_id": "<当前轨迹 track_id>", "other_track_id": "<对比轨迹 track_id>"}'
```

### `POST /api/checkpoint-visits` 检查点到访

- **参数**：`track_id`（必填，上传返回值）；`checkpoints`（必填，检查点列表，
  **最多 10 个**，超出返回 422）。每个检查点含 `lat` / `lon`（必填）、
  `radius_m`（可选，**1～1000 米**，默认 **50**，超出范围返回 422）、
  `name`（可选，最长 50 字符）。
- **返回**：`checkpoints`（与请求一一对应；每项含 `index`（序号，从 1 开始）、
  `name`、`lat` / `lon` / `radius_m`、`visit_count`（到访次数）、
  `total_duration_s`（累计停留秒数）与 `visits`（到访列表，按时间先后；
  每次含 `seg_index`（原始 `trkseg` 序号）、`start_time` / `end_time`
  （ISO 时间，穿越圆边界时为按线段比例插值的时刻，起止在圆内时为该连续记录的
  端点原始时间）、`duration_s`（停留秒数，恒为正））；未到访的检查点 `visits`
  为空数组）与 `thresholds`（口径：`max_checkpoints=10`、`min_radius_m=1`、
  `max_radius_m=1000`、`default_radius_m=50`、`max_gap_s=600`）。
- **错误**：轨迹相邻点时间未递增（零时差或倒序）时返回 `400` 与中文提示；
  `track_id` 不存在返回 `404`；检查点超过 10 个或参数越界返回 `422`。

示例：

```bash
curl -X POST http://localhost:8000/api/checkpoint-visits \
  -H "Content-Type: application/json" \
  -d '{"track_id": "<上传返回的 track_id>", "checkpoints": [{"lat": 31.0, "lon": 121.0, "radius_m": 50, "name": "家"}]}'
```
